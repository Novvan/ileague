# Risk-to-Task Map

Cross-references `ILEAGUE_PRD.md` §6's 6 Technical Risks to the exact task(s) that own their mitigation. A risk isn't "handled" until its owning task(s) are DONE per the Completion Status Protocol (tests/evals in the diff, acceptance criteria met with evidence) — this file exists so that check is a lookup, not a re-read of the whole plan.

| # | PRD Risk | Impact (per PRD) | Mitigation (per PRD) | Owning task(s) |
|---|---|---|---|---|
| 1 | Constraint-solver complexity grows non-linearly with player/venue count, causing slow or blocking bracket generation | Organizer-facing timeouts during event setup, directly hurts the Tournament Completion Rate success metric | Background worker job, not inline; <10s/64-player benchmark is the gate | **E4-T5** (Edge Function job wrapper + CI-enforced benchmark, `04-scheduling-engine.md`), **E4-T3** (the solver itself, property-based tests, `04-scheduling-engine.md`) |
| 2 | Organizer publishes an incorrect bracket without reviewing it | Player-facing schedule errors during a live event — the worst-case failure for this product | Mandatory `draft` → review → explicit `publish` state machine, publish UI shows a full schedule summary + confirmation before any data becomes player-visible | **E5-T4** (draft review/override UI + inline re-validation, `05-back-office.md`), **E4-T4** (conflict detector it depends on, `04-scheduling-engine.md`), **E5-T5** (publish confirmation step, `05-back-office.md`) |
| 3 | Realtime update latency or dropped Supabase Realtime connections in crowded venues with poor connectivity | Players see stale schedule data exactly when they need it most | Player App falls back to pull-to-refresh/periodic poll if the Realtime subscription drops | **E6-T5** (Realtime subscription + poll fallback, with a dropped-connection simulation test, `06-player-app.md`) |
| 4 | Time zone handling errors for remote/online cups spanning multiple regions | Wrong match times shown to players, defeats the core value proposition | Store all timestamps as UTC + IANA venue time zone at the data layer; never store or compute in local time server-side | **E2-T1** / **E3-T1** (UTC + IANA storage in the domain model and schema, `02-contracts-domain-model.md` / `03-supabase-infra.md`), **E4-T3** (Luxon-based server-side scheduling math, `04-scheduling-engine.md`), **E6-T7** (client-side local display via Dart `timezone`/`flutter_timezone`, `06-player-app.md`) |
| 5 | Supabase free-tier project auto-pauses after 7 days with no API traffic | Backend (and both apps) go dark for organizers/testers checking in on an inactive project | Scheduled health-check ping keeps the project active; accept as known risk until traffic is naturally frequent, or upgrade to Pro | **E1-T4** (GitHub Actions cron hitting the Nitro health endpoint, `01-repo-bootstrap.md`), activated via **E5-T1**'s real `/api/health` endpoint (`05-back-office.md`) |
| 6 | No backups/PITR on Supabase free tier during testing phase | A bad migration or accidental delete during early development has no recovery path | Acceptable while the dataset is test data with no real organizers depending on it; must resolve (upgrade to Pro) before any real, paying organizer's data goes live | **E3-T5** (posture doc + pre-flight checklist, `03-supabase-infra.md`), cross-referenced from **E7** (upgrade-off-free-tier triggers, `07-billing-tier-enforcement.md`) |

## Using this file

Before declaring the MVP "done" (all of E1–E7 complete), walk this table top to bottom and confirm each owning task actually shipped the named mitigation with a passing test that would catch a regression of it — not just that the task was marked complete. Risks 1, 2, and 3 each have a dedicated verification test named in their owning epic file (the CI benchmark, the conflict-blocks-publish test, and the dropped-connection simulation respectively); risks 4, 5, and 6 are more structural/documentary and should be spot-checked by reading the actual code/docs, not just trusting the task list.
